# 持久日志与重启诊断

> 目标：让路由器**断电也不丢关键日志**，并且下次开机后能一眼看出「上一次是正常关机还是异常断电」。

---

## 一、问题：默认日志「重启即失忆」

OpenWrt 默认把日志写在 tmpfs（内存盘）：

- `/var/log` 是 `/tmp` 下的目录，**重启即清空**
- 断电、看门狗复位、崩溃重启后，现场全部消失，只剩「怎么又重启了」的疑问
- `/proc/stat` 的 `btime` 只能告诉你「这次几点开机」，不能告诉你「上次怎么关的」

对一台长期无人值守的路由器，这等于**每次异常重启都无法事后取证**。

---

## 二、方案：日志落盘 + 启动历史

两件事分开做：

| 功能 | 实现 | 位置 |
|---|---|---|
| 系统日志持久化 | logd 直接把 syslog 写到闪存，按大小轮转 | `/etc/log/messages`（+ `.old`） |
| 启动历史与关机性质 | 自定义 init 脚本，每次开机追加一行 | `/etc/log/boot-history.log` |

### 2.1 日志落盘（UCI）

```sh
uci set system.@system[0].log_file='/etc/log/messages'
uci set system.@system[0].log_size='512'      # 单位 KB，当前文件上限
uci commit system
/etc/init.d/log restart
```

效果：`logd` 以 `-S 512` 运行，日志直接写 `/etc/log/messages`；
写满后轮转为 `messages.old`，总占用约 1MB（512KB × 2）。

### 2.2 启动历史（init 脚本）

`/etc/init.d/boot-log`：

```sh
#!/bin/sh /etc/rc.common
START=99
STOP=01

start() {
    LOG=/etc/log/boot-history.log
    NOW=$(date '+%F %T')
    BTIME=$(awk '/btime/{print $2}' /proc/stat)
    UP=$(cut -d. -f1 /proc/uptime)
    if [ -f /etc/log/.clean_shutdown ]; then
        PREV="正常关机"
        rm -f /etc/log/.clean_shutdown
    else
        PREV="异常断电/复位"
    fi
    echo "$NOW  boot  btime=$BTIME  uptime=${UP}s  prev=$PREV" >> "$LOG"
    if [ -f "$LOG" ] && [ "$(wc -l < "$LOG")" -gt 200 ]; then
        tail -n 200 "$LOG" > "$LOG.tmp" && mv "$LOG.tmp" "$LOG"
    fi
}

stop() {
    touch /etc/log/.clean_shutdown
}
```

判定逻辑：

- **正常关机 / 重启**：关机流程会调用 `stop()`，留下 `/etc/log/.clean_shutdown` 标记；
  下次开机看到标记 → 记为 `prev=正常关机`，并删除标记。
- **异常断电 / 看门狗复位**：关机流程没机会执行，标记不存在 → 记为 `prev=异常断电/复位`。
- `btime` 与 `uptime` 一并记录，便于反推「上次运行到几点」。

启用：

```sh
chmod +x /etc/init.d/boot-log
/etc/init.d/boot-log enable
/etc/init.d/boot-log start      # 立即补一条本次开机记录
```

## 三、容量与写入速率（实测）

| 指标 | 实测值 |
|---|---|
| 稳态日志速率 | 约 **42 KB/小时**（0.7 KB/分钟） |
| 主要来源 | esurfingclient 心跳（~17%）、dnsmasq/DHCP（~18%）、dropbear（~5%）、collectd/UA2F/cron（各 2–4%） |
| 512KB 可覆盖 | 约 **24 小时**（含每次开机 20–40KB 的启动日志） |
| 256KB 可覆盖 | 约 12 小时 |

overlay 占用：日志总量约 1MB，加 boot-history（<10KB）。K2P overlay 剩余 3MB 左右时完全够用；
若空间紧张，可降到 256KB（约 12 小时）。

## 四、实战：一次「断电重启」的完整取证

### 4.1 现象

用户反馈「路由器好像重启过」，但 `logread` 里所有日志时间都显示 `15:13:26`，
看起来像「下午就开机了」。

### 4.2 取证

```sh
# 1. 本次真实开机时刻（btime 是内核校准过的真实时间）
awk '/btime/{print $2}' /proc/stat
# 1792596529 -> 2026-10-21 17:55:29

# 2. 启动历史
cat /etc/log/boot-history.log
# 2026-10-21 22:42:30  boot  btime=1792592142  uptime=1607s  prev=异常断电/复位
# 2026-10-21 22:44:02  boot  btime=1792593808  uptime=33s    prev=正常关机

# 3. 上次运行的最后写入时刻（假时钟由 sysfixtime 设置，反映的是文件系统 mtime）
ls -l /var/log/lastlog /var/log/wtmp

# 4. 排除项
logread | grep -iE 'panic|oops|Out of memory|killed process'   # 无输出
```

### 4.3 结论

- 上次系统最后活动：10-21 **15:13:26**；本次上电：**17:55:29**
- 中间空 **2 小时 42 分钟** —— 只有「断电」能解释（崩溃复位会立即重启，不会空这么久）
- 无 shutdown 日志、无 panic/OOM、无定时重启任务 → 排除软件原因
- JFFS2 挂载时有少量 orphan/dead 节点，是非优雅关机的典型痕迹

**判定：非正常断电（拔电/停电/插排断电/电源接触不良）后重新上电。**
`logread` 里的 `15:13:26` 是开机初期 `sysfixtime` 设置的假时钟，不是真实开机时间。

## 五、日常用法

```sh
# 本次/历次启动记录（一眼看出哪次是断电）
cat /etc/log/boot-history.log

# 断电前的最后一段日志（定位死机前发生了什么）
tail -100 /etc/log/messages

# 搜索错误
grep -iE 'error|fail|panic|oom|timeout' /etc/log/messages | tail -50

# 跨重启保留的历史（上一轮）
tail -100 /etc/log/messages.old
```

## 六、限制与取舍

1. **断电瞬间最后几秒可能丢**：logd 有写入缓冲，未落盘的日志会随断电消失；
   但绝大多数日志（含启动过程）都会保留。
2. **写闪存的磨损**：按 42KB/小时、1MB 总量轮转，NAND 每天只写几十次小块，
   相对擦写寿命可忽略；不要为了「全量日志」把 `log_size` 调到几 MB。
3. **不要用 `logread` 判断历史**：`logread` 读的是内存缓冲区，重启后只剩本次启动的内容；
   历史必须看 `/etc/log/messages`。
4. **可选增强：远程 syslog**。如果有多台设备/服务器，可把日志转发到远端（`log_ip`），
   彻底规避本机断电丢日志；单机场景下本地落盘已经够用。
