# 05 · 固定 IP 与远程访问

路由器本身跑通之后，实际使用中很快会遇到两个新需求：

1. 内网设备的 IP 老是变 —— 共享、挂载、转发全部失效；
2. 想从外面（机房 / 家里）远程连回宿舍的电脑。

这一篇解决这两件事：**静态 DHCP 保留** + **端口转发**。

---

## 一、为什么要固定 IP

DHCP 租约是有期限的（本项目配的是 12h）。租约到期、设备重连、或者路由器重启之后，
同一台设备完全可能拿到一个不同的 IP。

只要配置里有任何地方**写死了 IP**，它就会跟着一起失效：

- 端口转发（`dest_ip` 写死）
- Samba / NFS 共享路径
- 防火墙白名单、脚本里的目标地址
- 反向代理、监控探针

所以「按 IP 写死」的配置，前提都是**先把 IP 固定住**。

固定 IP 有两种做法：

| 做法 | 位置 | 优缺点 |
|---|---|---|
| 设备端静态 IP | 在每台电脑/手机上手动配 | 每台都要配，换网络要改，容易冲突 |
| **DHCP 静态保留** | 在路由器上按 MAC 绑定 | 一处配置、全网生效，设备侧仍走 DHCP ✅ |

本项目用后者。

---

## 二、静态 DHCP 保留

对应脚本：`scripts/70-set-static-ip.py`。

原理很简单：dnsmasq 里给每个 MAC 绑定一个固定 IP。设备来请求 DHCP 时，
只要 MAC 匹配就直接发这个 IP，设备侧无感知。

```
uci add dhcp host
uci set dhcp.@host[-1].name='PC-1'
uci set dhcp.@host[-1].mac='aa:bb:cc:00:00:01'
uci set dhcp.@host[-1].ip='192.168.1.201'
```

### 2.1 把动态地址池挪开

关键细节：**保留地址必须落在动态地址池之外**，否则动态分配可能先占掉它，导致冲突。

本项目把池子收成 `192.168.1.100 ~ 192.168.1.200`：

```
uci set dhcp.lan.start='100'    # 从 .100 开始
uci set dhcp.lan.limit='101'    # 共 101 个（.100 ~ .200）
```

而保留地址用 `201 ~ 204`，正好在池外，互不干扰。

### 2.2 查 MAC

不知道设备的 MAC，可以在路由器上查：

```sh
cat /tmp/dhcp.leases        # 租约表：MAC  IP  主机名
ip neigh show               # ARP 邻居表
```

### 2.3 生效与验证

改完 `uci commit dhcp` 后重启 dnsmasq：

```sh
/etc/init.d/dnsmasq restart
```

设备**需要重新走一次 DHCP**（重连网线 / 重新关联 WiFi / 执行 `ipconfig /renew`）
才会落到保留 IP。验证：

```sh
# 保留配置
uci show dhcp | grep -E 'host\[[0-9]+\]\.(name|mac|ip)'

# 实际租约（应与保留一致）
cat /tmp/dhcp.leases

# 在线状态：看 ARP，不要看租约
ip neigh show | grep '192.168.1.'
```

> ⚠️ **判断设备是否真在线，要看 ARP / 网桥转发表，不能只看 DHCP 租约。**
> 租约不会因为设备断开就立刻消失，要等到期才清。ARP 里 `REACHABLE` / `STALE`
> 才代表最近有过通信。

## 三、端口转发（RDP 远程桌面）

对应脚本：`scripts/71-set-rdp-portforward.py`。

内网电脑在 NAT 后面，外网默认连不进来。端口转发就是把 WAN 侧某个端口
映射到内网某台机器的某个端口。

### 3.1 为什么不能都用 3389

每台电脑的远程桌面都是 3389。如果 WAN 侧也全用 3389，只能映射到一台。
所以给每台分一个**不同的 WAN 侧端口**：

| WAN 侧端口 | 转发到 | 用途 |
|---|---|---|
| 33890 | 192.168.1.201:3389 | 1 号机 |
| 33891 | 192.168.1.202:3389 | 2 号机 |
| 33892 | 192.168.1.203:3389 | 3 号机 |
| 33893 | 192.168.1.204:3389 | 4 号机 |

对应规则：

```
uci add firewall redirect
uci set firewall.@redirect[-1].name='RDP-PC-1'
uci set firewall.@redirect[-1].target='DNAT'
uci set firewall.@redirect[-1].src='wan'
uci set firewall.@redirect[-1].src_dport='33890'
uci set firewall.@redirect[-1].dest='lan'
uci set firewall.@redirect[-1].dest_ip='192.168.1.201'
uci set firewall.@redirect[-1].dest_port='3389'
uci set firewall.@redirect[-1].proto='tcp'
uci set firewall.@redirect[-1].family='ipv4'
```

### 3.2 验证规则下发

```sh
uci show firewall | grep -E 'redirect\[[0-9]+\]\.(name|src_dport|dest_ip)'

# fw4 会编译成 nft 规则，应能看到 dnat
nft list ruleset | grep -E '3389[0-3]'
```

`counter packets 0 bytes 0` 表示还没有人连过，属于正常（计数从 0 开始）。

### 3.3 从外部连接

格式是 `<WAN地址>:<端口>`：

```
mstsc /v:1.2.3.4:33890
```

WAN 地址在路由器上查：

```sh
ip -4 addr show dev wan | grep inet
```

### 3.4 连不上的排查顺序

1. **外部到 WAN 地址本身通不通** —— 先在外部 `ping <WAN地址>`。
   校园网/运营商若对入向连接有策略限制（NAT、封端口），这一步就过不去，
   端口转发配得再对也没用。
2. **目标电脑是否开了远程桌面** —— Windows 里「设置 → 系统 → 远程桌面」打开，
   并确认防火墙放行 3389。
3. **目标电脑 IP 是否等于转发目标** —— 回到第 2 节确认静态保留生效。
4. **路由器上规则是否在** —— 回到 3.2 确认。

## 四、安全注意

开放端口转发等于**在 WAN 上开了一个洞**，务必注意：

- **只放行必要端口**。本项目只开了 4 个高位端口，WAN 区域入向策略仍是 `REJECT`。
- **改高位端口**。把 3389 换成 33890+ 之类的非默认端口，能挡掉大量扫描。
- **强密码 + 不要用默认账号**。RDP 暴露在公网是常见入侵入口。
- **能上 VPN 就别开转发**。如果条件允许（有公网 IP 且能跑 WireGuard），
  用 VPN 进内网再连 RDP，比直接暴露 3389 安全得多。
- **用完可临时关闭**：`uci delete firewall.<规则>` 或直接 `uci set firewall.<规则>.enabled='0'`。

> 检查基线时注意：一旦配了转发，`uci show firewall | grep redirect` 就**不再是空的**，
> 这是预期行为，不是配置错误。

---

## 五、小结

| 目标 | 手段 | 脚本 |
|---|---|---|
| 设备 IP 固定 | dnsmasq 静态保留 + 收窄地址池 | `70-set-static-ip.py` |
| 外网访问内网设备 | firewall DNAT 端口转发 | `71-set-rdp-portforward.py` |

两个脚本都是**幂等**的：同名条目先删后加，可以反复执行。
改完都是 `uci commit` + 重启对应服务，**重启路由器后依然生效**。
